### Existing dependency exception

The dependency audit reports [GHSA-848j-6mx2-7j84](https://github.com/advisories/GHSA-848j-6mx2-7j84)
in elliptic, a transitive dependency of the Hedera SDK. The advisory currently
lists no patched version. The existing [OSV policy](../../osv-scanner.toml)
records a scoped exception through 21 February 2027: its documented assessment
is that this dependency is used for ABI encoding while wallet signing uses
other libraries. That is an existing project assessment, not a new independent
proof of unreachability. This integration does not broaden the exception or
modify dependency versions. Review it again before release and on expiry.

## Known boundaries and supervisor questions

- Shared Raccoon authorization is an EVM smart-account path. Native Bitcoin,
  Hedera, and personal EVM signing retain conventional chain signatures.
- Provisioning uses a trusted dealer; distributed key generation is pending.
- Hedera linking compares public keys. Its authentication and ownership model
  should be reviewed separately from Bitcoin/EVM signed address proofs.
- Bitcoin currently reuses the sending address for change; fresh change/address
  discovery is future work, relevant to privacy and public-key exposure.
- Monero remains planned. Manual public-network verification and independent
  security review remain outstanding.
- Historical progress-report claims about signing being pending are superseded
  by the current integrated implementation. Those documents are retained unchanged.
